## 2. P0 细则（已全部完成）

### ✅ T01 有损解码保存前二次确认
- **现状**：`codec.rs` 在严格 UTF-8 失败后用 chardetng 猜测，非法字节替换为 `U+FFFD` 并置 `meta.lossy = true`；原先 `write_file` 不检查 `lossy`，保存即把原字节永久改写。
- **已完成**：
  1. Rust `write_file` 新增 `allow_lossy` 参数，`lossy && !allow_lossy` 直接拒绝；
  2. 前端保存前弹「编码有损，保存会改写原数据」，取消即中止，确认后按原编码写回并把 `lossy` 置回 false；
  3. 状态栏有损告警保留。
- **验收**：`lossy_save_requires_explicit_permission` 单测通过——拒绝时磁盘无写入，显式授权后可写。

### ✅ T02 脏标签 / 关窗拦截

1. **fixtures 被行尾归一化破坏**：`.gitattributes` 的 `text=auto eol=lf` 把 CRLF 测试样本转成 LF，Linux CI 报 fixture 断言失败 → 用 `src-tauri/fixtures/** -text` 标记为二进制并重新入库。
2. **watcher 测试在 CI 不稳定**：Windows 会先收到 size=0 的 truncate 事件、macOS FSEvents 不保证单次通知 → 改为「重试写入直到收到内容事件 + 按文件名断言」。
3. **macOS 路径规范化**：FSEvents 把 `/var/...` 报成 `/private/var/...`，监听集合匹配不到 → 监听时同时登记原始路径与 canonical 路径，匹配双查。
4. **clippy 阻断**：`fold(false, |a, b| a || b)` 被判 `unnecessary_fold` → 改为显式循环（保留副作用语义）。
