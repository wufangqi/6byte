## 1. 背景与目标

### 1.1 背景

6byte 是 AI Native 文本工作台（md / txt / 大日志），不是 IDE。用户需要把「当前桌子上的材料」放在一起：打开一个目录后能浏览、打开、切换文件，并与 grep、AI 改写咬合。

现有「打开文件夹」只摊平一层、限 40 个文件并一次性打开，目录稍深或文件稍多就不够用，也形不成「工作区」心智。

### 1.2 目标

1. 单个根目录作为当前工作区，左侧展示文件树。
2. 树只承担导航与打开，不承担工程管理、Git、重构。
3. 打开文件、去重、大文件、编码、grep、AI 全部复用现有路径，不引入第二套文件模型。
4. 性能与权限叙事不变：单根、懒加载、不预扫全树、不整树监听。

### 1.3 成功标准（一句话）

用户「打开文件夹」后左侧出现可折叠的文件树；子目录懒加载；双击/Enter 打开文件的行为与现网完全一致；关闭或更换工作区时树正确切换且不影响已开标签；中英界面、深浅主题、键盘操作与现有规范一致。

## 2. 非目标（明确不做）

| 不做 | 说明 |
|---|---|
| 多根工作区 | 同时只允许一个根 |
| Git 状态 / 分支 / diff 装饰 | 避免 IDE 化 |
| 文件拖拽移动 / 复制 / 重命名 / 删除 | v1 只读导航 |
| 树内新建文件 / 文件夹 | 后续可选 |
| 监听整棵树并实时刷新所有节点 | 仅手动刷新（§7 FT-33） |
| 默认打开方式 / 系统右键集成 | 属 M4 |
| 工程级忽略规则编辑器 | 仅内置默认忽略 |
| Ctrl+P 文件名模糊查找 | 后续单独立项 |
| 插件、主题图标包 | 不做 |
| 「打开文件夹同时批量打开一层文本」兼容开关 | **明确不做**：直接替换旧行为（v2 决策） |

## 3. 用户故事

1. 写文档的人：打开笔记目录后左侧看到结构，不必反复走「打开文件」对话框。
2. 看日志的人：打开 `logs/` 后展开日期子目录，打开某个 `.log`。
3. 用 AI 改写的人：从树打开的文件进入同一套标签页，可对选区执行润色 / 翻译 / 总结 / Ctrl+K。
4. 关心性能的人：打开含大量文件的目录不卡死，信任「轻量」承诺。

## 5. 性能与上限（硬约束）

| 项 | 上限 | 说明 |
|---|---|---|
| 工作区根 | 1 | 单根 |
| 单目录一次返回子项 | **2000** | 超出截断 + 提示；IPC 返回 `truncated` 与 `limit` |
| 已展开目录数 / 缓存节点数 | 200 个目录 / 5000 节点 | 超出拒绝继续展开并 toast 提示；v1 **不做 LRU**，避免复杂度 |
| 目录扫描 | 无预扫；仅懒加载 | 禁止打开文件夹时递归扫全树 |
| 渲染 | **必须**做虚拟滚动或分段渲染（先 300 行 +「显示更多」） | 2000 行直接渲染不可接受；P0 验收项 |
| 首屏 | 打开文件夹到树根可交互 ≤ 300 ms（本机 SSD、<200 子项） | PR 里附实测；不作为 CI 门禁 |

## 6. UI / 信息架构

### 6.1 与现有界面的关系

| 区域 | 现状 | 引入文件树后 |
|---|---|---|
| 标题栏左 | 图标 + 文件 + 视图 | 不变；「文件」菜单增加「关闭文件夹」，「视图」菜单增加「文件树」勾选项 |
| 标题栏右 | 模型服务 / 补全 / 模型 | 不变 |
| 主区 | 居中欢迎页或编辑器 | 有工作区时：左侧树 + 右侧（欢迎页或编辑器）；无工作区时保持现状，仅欢迎页多一个次要按钮 |
| 状态栏 | 就绪 / 文件信息 | 有工作区时可在左侧加一段极短「文件夹名」，不挤占现有信息（P1） |

原则：

1. 无工作区 + 无标签 = 今天的欢迎页，只多「打开文件夹」入口。
2. 有工作区 = 左侧默认显示树（除非用户折叠），右侧可以是欢迎页或编辑器。
3. 有标签 + 无工作区 = 与今天一致，全宽编辑器。
4. 视觉跟 `docs/ui-guidelines.md`：token、24px 级控件、与标题栏/标签栏高度对齐，不做重 IDE 侧栏。

### 6.2 布局（有工作区）

```
┌──────────────────────────────────────────────────────────┐
│ [图标] 文件  视图          补全  模型  [模型服务] ─ □ ×   │
├──────────────┬───────────────────────────────────────────┤
│ 文件夹名  ↻ ✕ │  标签1  标签2  …                          │
│ ~/proj/docs  ├───────────────────────────────────────────┤
│ ▼ src        │                                           │
│   note.md    │     编辑器 / 大文件预览 / MD 分屏           │
│ ▶ logs       │     （无标签时右侧仍显示欢迎页内容）        │
├──────────────┴───────────────────────────────────────────┤
│ 就绪 · 编码/EOL…（现有状态栏逻辑）                          │
└──────────────────────────────────────────────────────────┘
```

- 树默认 240px，可拖 160–400px；折叠后编辑区全宽，不留空白窄条。
- 树头：文件夹名、绝对路径（省略）、刷新、关闭。
- 目录行：箭头 + 名称；文件行：名称；活动文件用 `--accent-soft` 浅底 + 左侧 2px 强调色竖条（与标签选中态同系）。
- 字号 `--text-sm`，行高 22–24px，文件名 ellipsis + tooltip。
- 状态：根加载中 / 目录加载中 / 空文件夹 / 读取失败 + 重试 / 截断提示，均不遮挡标题栏。

### 6.3 可访问性

- `role="tree"` / `role="treeitem"`，目录节点 `aria-expanded`，选中节点 `aria-selected`，树容器 `aria-label`（复用「文件树」文案）。
- Roving tabindex：树上仅一个节点 `tabindex=0`，方向键移动焦点；`Ctrl+Shift+E` 把焦点移到树。
- 所有图标按钮有 `aria-label`；焦点环沿用全局 `:focus-visible`。
- 折叠侧栏时，树的焦点回到编辑器。

## 8. 数据模型与 IPC

### 8.1 前端

```ts
type WorkspaceRoot = { rootPath: string; rootName: string };

type TreeNode = {
  path: string;
  name: string;
  kind: "dir" | "file";
  children?: TreeNode[];
  state: "idle" | "loading" | "error"; // 目录展开状态
  error?: string;
  truncated?: boolean;
};
```

- 树状态放 zustand（建议扩展 `workspace` store 中的独立 slice；不进 `tabs`）。
- 持久化只存 `ainative.workspace = { version: 1, rootPath }` 与宽度/折叠；**不持久化整棵树**。

### 8.2 Rust / IPC

| 命令 | 入参 | 出参 | 说明 |
|---|---|---|---|
| `list_dir_children` | `{ path: string }` | `{ entries: [{ name, path, kind: "dir"\|"file", size?: number, mtime?: number }], truncated: boolean, limit: number }` | 只列一层；应用忽略与隐藏规则；跳过符号链接 |
| `reveal_in_os`（P1 可选） | `{ path }` | — | 资源管理器中显示；若无现成插件，Windows 用 `explorer /select,`，macOS 用 `open -R`，Linux 用 `xdg-open` 父目录 |

约束：

- 禁止递归；单次最多返回 2000 条（`truncated` 标记）。
- 入参 `canonicalize` 后校验；`..` 逃逸、文件当目录、无权限均返回可映射的中文错误。
- 忽略 / 隐藏 / 符号链接规则只在 Rust 实现一份，前端不复制。
- 「能否当文本打开」继续由 `open_document` 判断，树不做白名单。

## 10. 测试

### 10.1 Rust 单测

1. 只返回一层，不递归。
2. 忽略 `node_modules` / `.git` 等目录。
3. `.` 开头文件/目录不返回。
4. 超过 2000 条时 `truncated=true` 且 `entries.len()==2000`。
5. 文件路径当目录、 不存在路径、无权限路径返回错误。
6. 符号链接目录被跳过；合法路径可读。

### 10.2 前端纯函数单测

- 排序：目录优先 + `Intl.Collator` 顺序。
- 高亮：`samePath` 在根内匹配、跨根不匹配。
- 截断提示与 `limit` 展示。
- `treeWidth` / `treeHidden` 解析与钳制（非法值回默认）。

### 10.3 E2E（+2～3 步）

> 原生目录选择框无法用 CDP 驱动，因此 E2E 走**持久化恢复**路径，作为 seam：

1. 预置临时目录（含子目录与 txt），写入 `localStorage['ainative.workspace']` 后 reload。
2. 断言树根可见 → 展开子目录 → 双击文件 → 标签打开且内容正确。
3. 写入/切换根或点击「关闭文件夹」→ 树消失、标签仍在。
4. 若有「虚拟渲染」，断言首屏渲染行数受限（不渲染 2000 行）。
5. 现有 E2E 的步数与断言行数同步更新。

### 10.4 人工验收

含中文与空格路径、只读目录、无权限子目录、>2000 项目录截断、深浅主题、键盘操作、折叠/拖宽持久化、根被删除后的重启提示。

## 14. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 替换旧行为让老用户困惑 | 在 CHANGELOG/README/发布说明写明；菜单文案保持一致；首次打开文件夹不再弹「已打开前 40 个」 |
| 2000 项渲染卡顿 | P0 必须做分段/虚拟渲染；实测记录进 PR |
| 符号链接逃逸/循环 | v1 直接跳过符号链接，Rust 单测覆盖 |
| 原生目录框无法 E2E | 用 `ainative.workspace` + reload 作为 seam；原生框走人工验收 |
| 树状态与标签状态不一致 | 高亮只按 `samePath` 计算，不复制标签数据；跨根标签明确不高亮 |
| 工作区根与 session 冲突 | 独立 key + 版本号；仅主窗口读写；恢复失败清理并提示 |

## 16. 决策记录（v2 相对 v1.1 的修订）

| # | v1.1 | v2.0 | 原因 |
|---|---|---|---|
| 1 | 「打开文件夹」批量开 40 个标签，FT-30 建议加默认关闭的兼容设置 | **直接替换**，无兼容开关；删除旧命令与提示 | 产品确认；避免两套行为与死代码 |

| 3 | 虚拟列表「推荐，成本高可先不做」 | P0 **必须**分段或虚拟渲染 | 2000 行直接渲染与「轻量」承诺冲突 |
| 4 | FT-33 刷新语义模糊 | 刷新 = 重列根 + 所有已展开节点，保留展开状态 | 可预期、实现简单、覆盖外部变更 |
| 5 | E2E「建议 +2～3 步」未定义 seam | 明确用 `ainative.workspace` + reload 驱动，原生目录框不自动化 | 原生对话框 CDP 无法操作 |
| 6 | 未提符号链接 | 跳过符号链接目录/文件，规范化后校验根 | 防逃逸与循环 |
| 7 | 5000 节点 LRU 缓存 | 200 目录 / 5000 节点硬上限，超限拒绝展开；v1 不做 LRU | 降低实现复杂度 |

| 9 | 数据模型 `children?: TreeNode[] \| "loading" \| "error"` | 拆成 `children?` + `state` + `error?` | 类型清晰、渲染简单 |
| 10 | 名称「浅文件树」 | 「工作区文件树（单根、懒加载）」 | 实际支持任意深度，避免误解 |
